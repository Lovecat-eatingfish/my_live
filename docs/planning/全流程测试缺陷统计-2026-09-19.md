## 二、P0 缺陷明细（4）

### BUG-01 充值到账金额差 1（¥6 实到 599）
- **现象**：新用户充值 ¥6，提示"+600 已到账"，但 header 和钱包页显示 599；DB 账户余额为正确的 600
- **根因**：`getBalance` 对无账户用户缓存 `-1` 哨兵值（5 分钟）；充值回调 `incr` 只判断 key 存在就 `increment`，`-1 + 600 = 599`，缓存与 DB 从此分叉。送礼 `decr` 同理会污染
- **修复**：`QiyuCurrencyAccountServiceImpl.incr/decr` 先读缓存值，`-1` 哨兵改为删除缓存回源 DB
- **回归**：新用户（先查余额触发哨兵场景）充值 ¥6 → 页面显示 600，与 `t_qiyu_currency_account` 一致

### BUG-02 全站兜底图片裂图（"图片都有问题"的主因）
- **现象**：首页/管理端大量头像、封面裂图；连"默认占位图"本身也是裂的
- **根因**：12 个前端文件共 17 处兜底图使用外部服务 `via.placeholder.com`，该服务已失效——兜底图自己就是死链
- **修复**：全部替换为内联 SVG data URI（头像/封面两种，零网络依赖）
- **回归**：首页 16 张封面 0 裂图；管理端用户列表头像正常

### BUG-03 视频播放 / 巡查截帧 / 审核封面不可达
- **现象**：管理端直播巡查 46 张截帧图全部裂图；新发布视频的播放地址打不开；审核页封面裂图
- **根因**：后端 `public-endpoint` 配置为局域网 IP（`http://192.168.31.252:3000/minio`，经前端代理访问 MinIO），但 Vite dev server 默认只绑本机回环，局域网地址连接被拒（curl 000）
- **修复**：`web_live/vite.config.js` 与 `web_admin/vite.config.js` 增加 `server.host: true`
- **回归**：局域网视频 URL 从 000 → 200；巡查页 46 图全部加载

### BUG-04 im-core-server 的 Dubbo 模块启动失败（IM 投递链路断）
- **现象**：Netty 端口（38110/38115）正常、服务看似健康，但 `IRouterHandlerRpc` 从未导出，im-router 无真实 provider 可调，IM 消息路由实际不可用
- **根因**：启动脚本注入 `DUBBO_IP_TO_REGISTRY=127.0.0.1`，Dubbo 3.2 硬性拒绝回环地址（`Specified invalid registry ip`），整个 Dubbo 模块启动失败；消费端自检因应用级实例存在而"假通过"
- **修复**：`start-step-all.ps1` 改注入真实网卡 IP（192.168.31.252），与 Netty 写入 Redis 的寻址地址保持一致
- **回归**：30035 监听、Nacos 出现 `IRouterHandlerRpc` 实例、im-router 日志确认 `Available Invokers: 192.168.31.252:30035`；E2E IM 双向收发通过

## 三、P1 缺陷明细（4）

### BUG-05 Dubbo 消费端默认 1s 超时，冷启动首调必炸
- **现象**：访问"我的视频"等首次触达的接口报"系统异常"，日志为 `TimeoutException: server elapsed: 1013ms, timeout: 1000ms`，3 次重试全部撞墙
- **根因**：全部 16 个服务未配置 consumer 超时，默认 1000ms 对本机冷启动（连接池/MyBatis 首次初始化）过紧
- **修复**：16 个 `application.yml` 统一增加 `dubbo.consumer.timeout: 5000`
- **回归**：重启后 E2E 17/17 一次通过，无超时报错

### BUG-06 web_live 前端无法启动
- **现象**：`npm run dev` 报 `ERR_MODULE_NOT_FOUND: esbuild`
- **根因**：项目目录迁移破坏了 pnpm 的符号链接结构
- **修复**：删除 `node_modules` 后 `pnpm install` 干净重装
- **回归**：:3000 正常监听并可用

### BUG-07 管理端内容管理状态标签错误
- **现象**：刚发布、待审核的视频（status=2=审核中）被显示为"已下架"
- **根因**：状态标签只有二值判断 `status === 1 ? '已上架' : '已下架'`，未对齐 provider 枚举（1=上架 2=审核中 0=下架）
- **修复**：`web_admin/src/views/VideoPage.vue` 改为三态映射
- **回归**：视频 68 正确显示"审核中"

### BUG-08 启动脚本缺陷：顺序违反依赖 + 依赖环死锁
- **现象**：按 `start-step-all.ps1` 原顺序启动，stream-provider 会因引用未启动的 living/im-router 而自检失败退出
- **根因**：①脚本把 stream-provider 排在第 5 位，但其引用 `ILivingRoomRpc`/`ImRouterRpc`（手册已标注"建议修正"）；②更深一层：user↔living、living↔stream 在代码里互相引用成环，自检器强制 `check=true`，无论谁先起都无法通过
- **修复**：脚本重排依赖顺序（stream 移至 living/im-router 之后）；新增 `$ModuleExtraArgs` 机制，对环上两条弱边注入 `--qiyu.startup.ignore-references=ILivingRoomRpc / ILivingStreamRpc`
- **回归**：16/16 服务按序启动全部通过自检并注册 Nacos

### 8.2 已知问题更正

- "Element Plus 按钮自动化点击超时"根因补正：隐藏标签页（`document.visibilityState=hidden`）下浏览器暂停渲染，**transitionend 不触发**导致弹框关闭动画完成后 DOM 残留（opacity=0 但拦截点击）；真实用户可见窗口不受影响。测评时 JS 点击可绕过。

### 8.3 行为澄清（非缺陷）

- 视频流第一页看不到刚发布的视频：feed 按**热度**（play×0.4 + like×0.3，同分 id 倒序）排序，新视频 0 播放 0 点赞排在尾部，直达 `/video/<id>` 可正常观看。
